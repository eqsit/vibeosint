# VibeOSINT

VibeOSINT — инструменты для OSINT-исследований с агентом [Hermes](https://hermes-agent.nousresearch.com/docs/): поиск, проверка зацепок и отчёт с источниками. В этом репозитории находятся **два отдельных интерфейса**, а не две части одного приложения.

| Интерфейс | Где находится | Назначение |
| --- | --- | --- |
| **Obsidian-плагин, legacy** | `main.js`, `manifest.json`, `styles.css` в корне | Расследования на Canvas: связанные карточки, переписка и подключение Hermes по ACP. Сохранён без замены веб-панелью. |
| **Текущая веб-панель** | [`panel/`](panel/) | Браузерный чат, отдельные расследования, ход работы агента, вложения и живое Markdown-досье. Node.js backend, Python MCP-инструменты и Hermes ACP. |

Панель не требует Obsidian; установка плагина не разворачивает панель. Автоматической синхронизации Canvas и веб-досье нет.

> Это публикация кода и обезличенных примеров конфигурации, **не копия рабочего сервера** и не готовый публичный многопользовательский сервис. Ключи, учётные записи, авторизованные Telegram-сессии, история и результаты расследований не поставляются. У панели пока опубликован только готовый frontend `web/dist`, без исходного проекта и воспроизводимой frontend-сборки.

## Что уже работает

### Расследование и контекст

- Список расследований; отдельные переписка, текущая задача, вложения и отчёт для каждого расследования.
- Hermes через ACP: сообщения, события инструментов, остановка и уточнения во время работы. Нативный контекст Hermes привязан к панельной сессии, а не общий на всю панель.
- Сохранение переписки, отчёта и идентификатора нативной ACP-сессии на диске. После рестарта можно продолжить новым сообщением; **незавершённый ход не возобновляется автоматически**.
- Глобальный для панели выбор модели и reasoning. Изменение применяется со следующего хода; уже работающий запрос не переключается посередине.
- Модульные инструкции агента в `panel/prompts/` и рабочие правила в `panel/workspace/AGENTS.md`.

### Поиск и проверка

- Основной веб-путь Hermes: `web_search` через Serper и `web_extract` через Firecrawl. Плагин Serper и патч устойчивости веб-инструментов вынесены в `panel/integrations/hermes/`.
- Отдельный вспомогательный MCP-поиск: Serper, SearXNG и DuckDuckGo. Явный выбор движка не должен незаметно дополняться результатами другого; ошибки/CAPTCHA не считаются доказательством отсутствия информации.
- Телефон: нормализация и валидация, оператор/регион при наличии данных, ссылки на мессенджеры, веб-след. Ник: проверка профилей и веб-след. Email: MX, поиск и регистрации через Holehe. Домен: WHOIS/DNS. IP: reverse DNS и публичные сведения об ASN/провайдере/географии.
- Поиск по локальному каталогу OSINT Framework. Каталог помогает выбрать ресурс, но **не означает, что все перечисленные сайты автоматически интегрированы или доступны**.
- Опциональная работа с Telegram через собственные авторизованные аккаунты и доступные оператору боты: запросы, получение ответов и ссылок на отчёты, разрешение сущностей. Телефон и СНИЛС нормализуются перед соответствующими запросами.
- Для явно выбранного residential-маршрута есть отдельная проверка доступности. Если такой маршрут недоступен, инструмент не должен выдавать прямое соединение за residential.

### Досье и файлы

- Живой Markdown-отчёт: разделы, таблицы, добавление и исправление строк, удаление ошибок, заголовок и изображения. Обновления видны в панели по мере поступления фактов.
- Источники привязываются к конкретным строкам; исправление строки требует нового подтверждения, а не автоматического наследования старого источника. Утверждения пользователя отмечаются отдельно. Это проверка структуры доказательств, **не гарантия истинности текста по ссылке**.
- Vision-анализ изображений через отдельно настроенный OpenAI-совместимый endpoint.
- Рецепт Docker-окружения для терминала содержит Maigret, Holehe, Tesseract OCR с английским и русским, pypdf/reportlab, Poppler, ExifTool/Pillow и FFmpeg. Наличие этих утилит даёт агенту инструменты обработки, но не делает каждый формат отдельной готовой кнопкой интерфейса.

## Архитектура и границы изоляции

```text
Браузер ── HTTPS / reverse proxy ── Node.js / Express
                                      │ 127.0.0.1:3000
                                      ├── private data: sessions, uploads, auth, settings
                                      └── Hermes ACP: контекст на расследование
                                            ├── LLM-провайдер / свой API-шлюз
                                            ├── Serper + Firecrawl / веб-инструменты
                                            ├── Python MCP → OSINT, отчёт, vision, Telegram
                                            └── terminal → Docker sandbox
                                                            └── workspace / разрешённые mounts
```

- Сервер панели, ACP и MCP работают **на хосте**. В Docker направлены terminal-вызовы Hermes, а не весь стек.
- Workspace и нужные для проекта файлы могут быть доступны контейнеру через bind mounts. Docker здесь не равен полной изоляции от данных и сети хоста.
- Не публикуйте Docker socket и не считайте доступ к Docker непривилегированным. Для публичного развёртывания нужны отдельный системный пользователь, ограничения процессов и проверка mount-политики.
- Node и MCP совместно изменяют JSON-сессии с блокировками и атомарной записью. Это файловое хранилище, не кластерная БД.
- Telegram использует **один канонический проектный пул**: хост и Docker должны видеть одни SQLite-файлы и одни lock-файлы. Независимые копии пула нарушают согласованность состояния и квот.
- Межпроцессный `flock` по UID удерживается до завершения disconnect; занятый аккаунт возвращает busy. Неопределённый/запаздывающий ответ вызывает cooldown, а не немедленное переиспользование диалога. Время наблюдения квоты отделено от LRU-выбора аккаунта.

## Что нужно оператору

| Компонент | Что предоставить самостоятельно |
| --- | --- |
| Хост | Linux, Git, Node.js **≥ 22.19.0** (требование закреплённого `undici`), Python **3.11+** как рекомендуемое окружение, `venv`/pip, Docker для terminal backend. |
| Hermes | Собственная установка с ACP и MCP; отдельный `HERMES_HOME`, конфигурация, доступ к выбранной модели. [Официальная документация](https://hermes-agent.nousresearch.com/docs/). |
| Модель | Рабочие credentials провайдера или собственного совместимого шлюза, баланс/подписка и доступ к модели. Список в UI сам по себе доступа не даёт. |
| Панель | Собственный случайный `PANEL_PASSWORD` длиной не менее 16 символов; закрытые каталоги для истории и uploads. |
| Веб-поиск | `SERPER_API_KEY` для основного Serper-пути. Собственный SearXNG — опционально, настраивается через `OSINT_SEARXNG_URL`. |
| Извлечение страниц | Доступный Firecrawl. `FIRECRAWL_API_KEY` нужен при работе с ключевым API; keyless fallback зависит от внешней службы и не гарантирован. |
| Изображения | `OSINT_VISION_BASE`, `OSINT_VISION_MODEL`, при необходимости `OSINT_VISION_KEY`; endpoint должен принимать изображения, а не только текст. |
| Telegram, опционально | Свои Telegram API credentials, заранее авторизованные Telethon SQLite `.session`, согласованные state JSON и права/квоты нужных ботов. JSON с перечнем аккаунтов **не заменяет авторизацию**. |
| Residential, опционально | Свой работающий прокси/туннель и право им пользоваться. В репозитории прокси и домашний компьютер не предоставляются. |
| Публичный доступ | Домен, TLS и собственный reverse proxy; резервное копирование и защита сервера. Для локального запуска домен не нужен. |

### Модельная политика — не универсальная матрица провайдеров

В `panel/server/model_policy.mjs` предусмотрены три UI-значения:

- `opencode-go/deepseek-v4.1-flash`;
- `codex/gpt-6.1-sol`;
- `agy/gemini-3.8-flash-high`.

Это ID/алиасы текущей интеграции. Их наличие у вашего провайдера, параметры reasoning и тарифы нужно проверить самостоятельно. В ACP первый маршрут преобразуется в `opencode-go:deepseek-v4.1-flash` и использует настроенного провайдера с `OPENCODE_GO_API_KEY`; остальные направляются как `custom:<model>` в настроенный совместимый шлюз. Шлюз и его credentials в репозиторий не входят. Не заменяйте `/` и `:` наугад: маршрутизация зависит от формы ID. Неподдерживаемая модель отклоняется; бесшумная замена другой моделью не является обещанным поведением.

## Развёртывание панели

Это последовательность ручной установки, **не заявление о проверенном one-click bootstrap**. Все команды ниже выполняются на вашей копии, не на уже работающем сервере с пользовательскими данными.

### 1. Получить код и зависимости

```bash
git clone https://github.com/eqsit/vibeosint.git
cd vibeosint/panel
npm ci --prefix server
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Не путайте `panel/requirements.txt` для хостовых Python/MCP-скриптов с расширенным `panel/infra/sandbox-requirements.txt` для контейнера. Hermes устанавливается отдельно по официальной инструкции; установка зависимостей панели его не устанавливает.

### 2. Создать закрытые каталоги и настройки

```bash
umask 077
mkdir -p data/sessions data/uploads
cp .env.example .env
chmod 600 .env
```

Заполните **свою** `.env`, не коммитьте её. Рекомендованный `scripts/run-panel.sh` использует `server/standalone.mjs`: пути данных, workspace, prompts, frontend и MCP разрешаются внутри текущего `panel/`, а отдельный Hermes home — в `panel/.hermes-home`. Относительные overrides разрешаются относительно `panel/`, поэтому смена cwd дочернего процесса не меняет их смысл. Прямой запуск legacy `server/index.mjs` сохраняет исходные `/opt/vibeosint` defaults и требует ручной настройки.

Минимально согласуйте `PANEL_DATA_DIR` с `OSINT_DATA_DIR`, `PANEL_UPLOADS_DIR` с `OSINT_UPLOADS_DIR`, а также `PANEL_WORKSPACE_DIR`, `PANEL_PROMPTS_DIR`, `PANEL_WEB_DIST`, `OSINT_ENGINE_SCRIPT`, `OSINT_FRAMEWORK_PATH`, `HERMES_BIN` и `HERMES_HOME`. Примеры конфигурации — отправная точка, а не действующие credentials.

### 3. Подготовить отдельный Hermes

1. Установите Hermes из официального источника и настройте собственную модель/провайдера в отдельном `HERMES_HOME`. Не копируйте чужой домашний каталог, auth store, историю или runtime generation.
2. Подключите MCP-сервер `osint`: команда — **абсолютный путь** к `panel/.venv/bin/python`, аргумент — абсолютный путь к `panel/scripts/run_mcp.py`, транспорт stdio. Шаблон — [`panel/config/hermes.example.yaml`](panel/config/hermes.example.yaml); замените абсолютные placeholder-пути и внесите параметры через конфигурацию своего Hermes.
3. MCP получает отфильтрованное окружение. Обёртка `run_mcp.py` поэтому явно читает только локальную, исключённую из Git `panel/.env`, задаёт абсолютные пути и затем запускает сервер. Общие настройки Node/MCP храните в этой `.env`; переменные, заданные только в shell родителя, при необходимости явно передавайте MCP штатным механизмом своей версии Hermes. Не публикуйте config с развёрнутыми секретами.
4. Установите Serper-плагин из `panel/integrations/hermes/plugins/web/serper/` в отдельный Hermes home. Конфигурация интеграции: `plugins.enabled` включает `web-serper`, `web.search_backend: serper`, `web.extract_backend: firecrawl`. Ключ Serper хранится отдельно от публичного config.
5. Проверьте совместимость `panel/integrations/hermes/patches/web-resilience.patch` со своей версией Hermes. Базовая ревизия патча: `e6f57427c198cfd96854522b7a9159eb007e13c2`. **Не применяйте патч вслепую к произвольной новой версии**; сначала проверка применимости и соответствующие тесты в отдельной копии.
6. Настройте `terminal.backend: docker`, образ ниже и рабочую папку панели. Сохраняйте только необходимые mounts; проверьте из терминала агента, что команда исполняется в контейнере, а не на хосте.

Настройки Hermes вносите его штатными командами конфигурации. Схему конкретной установленной версии сверяйте с [руководством по конфигурации](https://hermes-agent.nousresearch.com/docs/user-guide/configuration), а не с приватной инсталляцией автора.

### 4. Собрать окружение терминала

Из каталога `panel/`:

```bash
docker build -t vibeosint-sandbox:local -f infra/sandbox.Dockerfile infra
```

Укажите `vibeosint-sandbox:local` в `terminal.docker_image` отдельного Hermes. Базовый образ и Python-пакеты скачиваются из внешних registry; сборка требует сети. Проверьте OCR `eng`/`rus`, PDF и нужные CLI внутри фактического контейнера. Образ не должен содержать ключи, авторизованные аккаунты или результаты расследований.

### 5. Подключить только нужные внешние функции

- Без Telegram начните с общедоступного домена и веб-поиска. Не создавайте фиктивный авторизованный пул.
- Для Telegram подготовьте свои API credentials и сессии вне Git; задайте имена доступных **вам** ботов. Учитывайте условия источника, согласие и законность обработки. Чужие боты/подписки с авторского сервера не являются частью продукта.
- Согласуйте state JSON с реальными UID и существующими SQLite-сессиями. Канонический пул и каталог `.tg-runtime` должны быть общими для host/Docker; права каталогов — `0700`, файлов сессий/состояния — `0600`. Не удаляйте lock-файлы во время работы и не запускайте те же аккаунты параллельно в обход проектных блокировок.
- Для vision задайте собственный endpoint/модель/ключ; для residential проверьте именно выбранный маршрут. Ошибки необязательной интеграции не следует скрывать успешностью другой.

### 6. Запустить и проверить

Из `panel/`, после заполнения `.env`:

```bash
./scripts/run-panel.sh
```

Скрипт явно передаёт Node `--env-file-if-exists` и запускает portable entry point. Без заполненного `PANEL_PASSWORD` сервер откажется стартовать. Он слушает `127.0.0.1:3000`, если не изменён `PANEL_PORT`. Откройте браузер на этой машине либо используйте свой SSH-туннель; для внешнего доступа поставьте HTTPS reverse proxy на loopback upstream. Сохраняйте корректные `Host`, `X-Forwarded-Proto` и origin; не отключайте cookie/Origin-проверки ради обхода ошибки конфигурации.

После входа: создайте тестовое расследование, попросите прочитать `https://example.com`, проверьте настоящий URL в источниках и обновление досье, затем проверьте terminal backend и возобновление контекста новым сообщением. Vision и Telegram проверяйте отдельно только на разрешённых тестовых данных. Внешний smoke расходует квоты; offline-тесты ниже — нет.

Перед оформлением systemd unit задайте своего пользователя, рабочую папку, абсолютный `ExecStart` и защищённый файл окружения. Production unit, TLS-сертификаты и настройки чужого хоста не входят в обязательный bootstrap.

## Переменные окружения

Имена ниже читает код панели. В таблицах указаны исходные defaults backend; рекомендованный standalone launcher заменяет deployment-пути на пути текущего checkout и `HERMES_BIN=hermes`. ## Работа с панелью и API

1. Войдите собственным паролем.
2. Создайте расследование и укажите цель, допустимые источники и границы задачи. Начинайте с проверяемого публичного объекта.
3. Следите за шагами и источниками, задавайте уточнения. Остановку используйте до смены инфраструктуры или перезапуска процесса.
4. Проверяйте таблицы досье по первоисточникам. Уточнение модели не превращает неподтверждённое совпадение в установленную личность.
5. После рестарта при необходимости отправьте «продолжай»: сохранение истории не означает автозапуск оборванного запроса.

Основные маршруты:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/auth/login` | JSON `{"password":"…"}`; установка auth-cookie, без токена в JSON. |
| `GET` | `/api/auth/check` | Проверка cookie. |
| `POST` | `/api/auth/logout` | Выход и отзыв текущей сессии авторизации. |
| `GET` / `POST` | `/api/sessions` | Список / создание расследования. |
| `GET` / `PATCH` / `DELETE` | `/api/sessions/:id` | Чтение / обновление / удаление расследования. |
| `POST` | `/api/sessions/:id/chat` | Сообщение `{text, images?}`; активность затем читается из состояния сессии. |
| `POST` | `/api/sessions/:id/stop` | Остановка текущего хода. |
| `POST` | `/api/sessions/:id/reset-chat` | Сброс переписки/нативного контекста с сохранением досье. |
| `GET` | `/api/health` | Авторизованная проверка backend. |

Защищённые маршруты используют **cookie**, а не Bearer/query-токен. Авторизационная cookie `osint_token` — HttpOnly, SameSite=Strict; Secure зависит от корректно определённого HTTPS. Токен не предназначен для localStorage. У входа есть throttling; это не полноценная система пользовательских rate limits и квот ресурсов.

## Тесты и статус проверки

Из `panel/`, в отдельной тестовой копии и с установленными зависимостями:

```bash
# Python + Node regressions и оба вспомогательных smoke-теста
./scripts/run-tests.sh

# Отдельный локальный HTTP/auth + реальное MCP list_tools/report readback
# Без LLM-вызовов, Telegram-запросов и внешнего поиска
.venv/bin/python scripts/smoke_local.py
```

Не запускайте тесты с production data dir, живыми пользовательскими сессиями или случайно унаследованными секретами. Проверки сетевых интеграций и offline-регрессии — разные уровни: зелёные unit-тесты не подтверждают работоспособность внешнего бота или платного API.

**Подтверждённая исходная точка:** перед публикацией в развёрнутой исходной версии прошли 57 Node-тестов, 91 Python-тест и 193 теста выделенного веб-набора модифицированного Hermes. Последний набор относится к runtime Hermes и не является ещё 193 тестами панели. Это количество пройденных проверок, **не процент покрытия**, не benchmark качества OSINT и не гарантия отсутствия ошибок.

**Очищенный экспорт проверен повторно:** 96 Python-тестов, 60 Node-тестов, оба вспомогательных smoke-теста, локальный запуск UI/auth, обнаружение 19 MCP-инструментов и чтение синтетического досье через настоящий stdio MCP. Для этого созданы отдельная новая Python venv из `requirements.txt` и Node-зависимости через `npm ci`; `pip check` прошёл. Эти проверки не требуют приватных аккаунтов или API-ключей. Добавлен workflow [Panel checks](.github/workflows/panel-checks.yml); его текущий результат смотрите в GitHub Actions, а не считайте неизменно зелёным.

Это **не** проверка полностью новой машины с самостоятельно настроенным Hermes, платной моделью, внешними API и Telegram. Для патча Hermes 193 runtime-теста запускаются в совместимой копии самого Hermes, а не командой тестирования Node-панели.

## Безопасность и приватность

- Используйте проект только для законных задач, с необходимыми правами и минимизацией персональных данных. Доступность источника или Telegram-бота не делает обработку любых сведений допустимой.
- В публичной копии **не должны быть** `.env`, API-ключи, пароли, OAuth/auth-файлы, SSH-ключи, реальные UID/телефоны, Telegram `.session`/WAL/SHM, state JSON с аккаунтами/квотами, auth-cookie, история, uploads, отчёты, логи и бэкапы рабочего сервера.
- Пользовательские данные должны храниться вне отслеживаемого дерева либо в явно исключённых каталогах. `.gitignore` не удаляет уже закоммиченные секреты из истории: перед публикацией проверяйте и staging, и историю; при утечке отзывайте ключи.
- Запросы, фрагменты документов, изображения и результаты инструментов могут уходить в LLM, поиск, vision endpoint и другие выбранные внешние службы. «Self-hosted панель» **не означает**, что данные никогда не покидают сервер.
- Внешние страницы и ответы инструментов — недоверенный ввод. Prompt injection, ошибочные совпадения, вредоносные файлы и чрезмерные полномочия инструментов остаются рисками. Не давайте агенту доступ к личному home, секретам и неограниченному хостовому shell.
- Держите backend на loopback; наружу — только HTTPS через корректно настроенный proxy. Ограничивайте доступ сетевыми правилами/VPN, проверяйте права файлов, mount-политику и резервные копии.
- Это пока общая парольная авторизация, не отдельные пользователи/организации с разграничением данных. Не выставляйте панель как общедоступный SaaS без дальнейшего hardening.
- Резервное копирование сессий Telegram требует согласованного SQLite backup, а не копирования активной базы наугад. Храните бэкапы шифрованно, отдельно от mounts агента; проверяйте восстановление.

## Ограничения

1. **Frontend опубликован как готовый `web/dist`.** Исходники React/TypeScript, исходные зависимости и полноценный build pipeline пока не восстановлены. Команды `npm run dev/build` для frontend здесь не обещаны.
2. **Это не мультиарендный сервис:** общая авторизация и глобальные модельные настройки, нет полноценного RBAC, изолированных организаций и неизменяемого аудита действий.
3. **Изоляция частичная:** только terminal backend в Docker; MCP/ACP/Node и часть сетевых вызовов остаются на хосте.
4. **Внешние зависимости меняются:** API, страницы, боты, квоты, геоблокировки, CAPTCHA и keyless extraction могут отказать. Ни всех провайдеров, ни бесперебойность каждого источника проект не гарантирует.
5. **Telegram не включается из коробки.** Нужны реальные разрешённые авторизованные аккаунты и их state. Исходное развёртывание проверялось на проектном пуле из 10 аккаунтов; эти аккаунты и их идентификаторы не поставляются, это не требование купить ровно 10 аккаунтов.
6. **Отчёт требует проверки человеком:** ссылка и корректная таблица не подтверждают факт автоматически; особенно важны однофамильцы, смена владельца номера/ника и устаревшие сведения.
7. **Нет автоматического resume оборванного хода**, полной очереди тяжёлых задач и гарантированного распределения ресурсов между расследованиями. Много ACP-процессов/браузеров/CLI может перегрузить хост.
8. **Файловое JSON-хранилище** и локальные locks не являются готовой схемой горизонтального масштабирования.
9. **Совместимость Hermes привязана к интеграции/ревизии.** Патч и плагины требуют проверки после обновлений; нельзя обещать независимость от версии runtime.
10. **DEEP-режим относится к сохранённой legacy-документации плагина**, не к текущей веб-панели: в панели нет отдельного переключателя или команды `/deep`.

- Минимальные привилегии host-процессов, явная политика egress/mounts, дальнейшая изоляция MCP и обработчиков файлов.

### P2 — приоритет продуктовой разработки: интерфейс, факты, восстановление

Весь список ниже **ещё не реализован**. Первый продуктовый приоритет — интерфейс + карточки фактов + восстановление; восстановление frontend-сборки из P0 должно предшествовать крупной UI-работе.

- **Обычная агентная оболочка:** понятная лента диалога, раскрываемые tool steps, текущий план/статус, остановка и уточнения; досье и источники — рядом, как отдельный рабочий артефакт. Не наращивать постоянные ручные правки минифицированного bundle.
- **Карточки фактов:** значение, источник, дата наблюдения и явный статус «подтверждено / не проверено / противоречие»; ручная проверка и связь с досье. Не показывать выдуманный процент уверенности и не называть текущую проверку URL уже готовой системой фактчекинга.
- **Страница доказательств:** сохранённые снимки страниц/скриншоты с исходным URL и датой получения. Это отдельная будущая возможность, не нынешнее прикрепление картинки.
- **Восстановление после рестарта:** checkpoints выполненных шагов, учёт уже оплаченных запросов и безопасное продолжение без их необоснованного повтора. Сохранённая сегодня переписка/ACP ID не равна такому механизму.
- **Бюджеты расследования:** время, количество запросов и стоимость; честные состояния «ожидание квоты», «источник недоступен» и «нужно действие оператора». Текущий backend timeout не заменяет бюджет и очередь.
- **Экспорт PDF/HTML:** готовое досье вместе с источниками, изображениями и статусами фактов. Наличие reportlab/Markdown сейчас не означает, что такой экспорт в UI уже есть.

### P3 — качество и расширение интеграций

- Контрактные тесты внешних источников, сверка разных источников и качество доказательств.
- Настраиваемая модельная политика и проверяемые адаптеры **конкретных** провайдеров, без обещания поддержки всех возможных API.
- При необходимости — БД и worker-архитектура для масштаба; обмен с Obsidian только как отдельная спроектированная функция.
- Веб-граф связей и multi-agent-режим — более поздние, опциональные направления, не замена первым трём приоритетам. Существующий legacy Canvas в Obsidian уже сохранён отдельно.
