# VibeOSINT — внешний Hermes ACP

Готовая модификация Obsidian-плагина https://github.com/eqsit/vibeosint.
Версия: **1.2.1**. Основа: commit `6bacb58210fe57256d1d11ed67d6752c1c10cc2a`.
Изменения сделаны для подключения своего Hermes локально, на сервере через SSH
или через произвольную команду, которая предоставляет ACP по stdin/stdout.

## Установка архива

1. Распакуйте папку плагина из ZIP в `<ваш vault>/.obsidian/plugins/`.
2. Если плагин уже установлен, сначала отключите его. Замените программные файлы;
   сохраните свои `data.json` и `chats.json` — в архиве их нет.
   При переходе со старой сборки перенесите эти два файла в новую папку `vibeosint`.
3. Перезапустите Obsidian и включите установленный плагин
   в Settings → Community plugins.
4. Откройте настройки плагина и настройте подключение **Hermes ACP**.

Плагин уже готов к запуску: Node.js, npm и сборка пользователю не нужны.
Рабочие файлы — `main.js`, `manifest.json`, `styles.css`.
Это десктопный плагин; мобильный Obsidian не поддерживается.
## Внешний Hermes на сервере: SSH

Hermes должен быть установлен и настроен **на сервере**: модель, ключи, инструменты
и при необходимости профиль. На компьютере с Obsidian нужен только OpenSSH.
SSH запускает отдельный процесс `hermes acp` на сервере и передаёт протокол по
зашифрованному соединению. Не требуется открывать ACP-порт или устанавливать
HTTP/WebSocket-мост.

Сначала проверьте обычное подключение к серверу в терминале компьютера с Obsidian:

```bash
ssh user@server
```

При первом подключении проверьте и подтвердите отпечаток сервера. Настройте вход
по ключу или через ssh-agent. Парольные запросы внутри плагина не поддерживаются:
SSH запускается с `BatchMode=yes`, без PTY. Зашифрованный ключ заранее добавьте в
ssh-agent. Настройки Host, ProxyJump, IdentityFile и прочие параметры из
`~/.ssh/config` учитываются; можно указать Host-алиас вместо `user@server`.

На сервере можно выяснить путь к установленному Hermes:

```bash
command -v hermes
hermes acp --check
```

В настройках плагина заполните:

| Поле | Пример / значение |
| --- | --- |
| Транспорт | Внешний Hermes · SSH |
| SSH-хост | `user@server` или SSH-алиас |
| SSH-порт | Пусто: из SSH config, иначе 22; можно указать свой |
| SSH-ключ | Пусто: SSH config / ssh-agent; либо локальный путь `~/.ssh/id_ed25519` |
| Программа SSH | `ssh`, либо полный путь к `ssh` / `ssh.exe` |
| Команда ACP | Путь, полученный через `command -v hermes`, например `/home/user/.local/bin/hermes` |
| Аргументы ACP (JSON) | `["acp"]` |
| Рабочая папка Hermes | Существующая папка НА СЕРВЕРЕ, например `/home/user` |
| Переменные окружения | `{}`; обычно ничего добавлять не требуется |
| Модель Hermes | Пусто: использовать модель из конфигурации Hermes |

**Замените `user`, `server` и пути своими значениями.** Затем нажмите
**«Применить и проверить»**. Кнопка проверяет ACP initialize и session/new;
запрос к языковой модели для проверки не отправляется. При заполненном поле
модели также проверяется её переключение.

Если используется отдельный уже созданный профиль Hermes, укажите аргументы:

```json
["-p", "obsidian", "acp"]
```

Профиль `obsidian` больше не навязывается. Скиллы и скрипты автора исходного плагина
не входят в архив и для самого подключения не требуются. Агент использует
инструменты, доступные в вашей установке Hermes.

## Как работает Canvas с удалённым агентом

Canvas остаётся в локальном Obsidian. Плагин передаёт текстовый контекст текущего
холста в запросе, получает потоковый ответ и применяет JSON-блоки изменений
карточек локально. Папку vault на сервер копировать не нужно.

Удалённому Hermes не предоставляется клиентский доступ к файлам/терминалу Obsidian.
Его собственные инструменты выполняются на сервере в указанной рабочей папке.
Локальные вложения, картинки и произвольные файлы vault автоматически не
синхронизируются. Контекст текущего холста и введённый запрос отправляются агенту
и выбранному им провайдеру модели.

Это подключение к **ACP stdio через SSH**, а не к URL веб-интерфейса Hermes,
OpenAI API или уже открытой интерактивной CLI-сессии. Для каждого подключения
создаётся ACP-процесс; для каждого холста — отдельная сессия. После разрыва
соединения создаются новые сессии: контекст берётся из текущего холста, переписка текущего холста передаётся новой сессии (до 80000 последних символов,
без повторной передачи старых JSON-действий). Внутреннее состояние инструментов не восстанавливается. История чата
плагина остаётся в `chats.json`.

## Локальный Hermes

Выберите **Локальный Hermes · stdio**. Команду можно оставить пустой для
автоматического поиска либо задать полный путь. Аргументы: `["acp"]`.
Пустая рабочая папка означает папку vault.

На Windows укажите `hermes.exe`. Если установка предоставляет только Python,
можно указать абсолютный путь к Python из окружения Hermes и аргументы
`["-m", "acp_adapter.entry"]`. Файлы `.cmd` / `.bat` напрямую не запускаются.

## Своя команда ACP

Режим **Своя команда · stdio** позволяет использовать обёртку или другой ACP-агент.
Команда — отдельное имя/путь исполняемого файла, аргументы — JSON-массив строк.
Команда запускается без shell, поэтому кавычки вокруг пути в поле не нужны.
stdout должен содержать JSON-RPC ACP, разделённый переводами строк; диагностика
должна идти в stderr. Адреса `http://` / `ws://` в этом поле не поддерживаются.

Для обёртки, работающей с удалённым агентом, поле рабочей папки передаётся этому
агенту как `session/new.cwd`. Сама обёртка запускается в локальной папке vault.
При SSH сервер должен использовать POSIX-совместимую shell.

## Настройки и разрешения

Изменения полей сохраняются автоматически, но активное подключение использует
предыдущие значения до **«Применить и проверить»** или перезапуска плагина.
Кнопка не прерывает активные запросы: сначала завершите или остановите их.
Изменение модели через `/model ID` применяется к текущему холсту и используется
для новых сессий; уже открытые другие сессии сохраняют свою модель.

Переключатель **«Автоматически разрешать инструменты»** по умолчанию **включён**:
запросы разрешений от Hermes подтверждаются без диалога в Obsidian. Выключите его,
чтобы подтверждать каждое действие вручную. Плагин по-прежнему не принуждает
Hermes к YOLO-режиму и не отключает проверки его конфигурации. Если сам Hermes
уже настроен работать без подтверждений, он может не присылать запросы разрешений.

## Прокси для локального ACP

В режиме **Локальный Hermes · stdio** доступно поле **«SOCKS5-прокси»**. Адрес
не подставляется в окружение процесса: он передаётся Hermes в промпте вместе с
инструкцией повторять через прокси запросы, упавшие с 403 Forbidden, RegionError,
Connection Reset или блокировкой Cloudflare. Пустое поле — прокси не упоминается.

Формат: `socks5h://127.0.0.1:2080`, `http://proxy.local:8080` либо просто
`127.0.0.1:2080` — в последнем случае подставляется схема `socks5h`. Она резольвит
DNS на стороне прокси и не даёт утечки DNS. Схемы: `socks5h`, `socks5`, `socks4`,
`http`, `https`. Некорректный адрес отклоняется по кнопке «Применить и проверить».

Для SSH поле не показывается: удалённый Hermes ходит в сеть с сервера, и локальный
адрес вроде `127.0.0.1:2080` там не существует. Прокси для удалённого агента
задавайте в его конфигурации на сервере или через «Переменные окружения»
(`{"ALL_PROXY":"socks5h://127.0.0.1:2080"}` — адрес будет резолвиться на сервере).

В SSH передаются только явно заданные переменные из поля «Переменные окружения»;
локальные ключи API и настройки прокси автоматически на сервер не копируются.
JSON окружения сохраняется открытым текстом в `data.json`. Секреты удобнее
оставить в конфигурации Hermes на сервере. Приватный SSH-ключ остаётся локальным;
в настройках хранится его путь, не содержимое.

## Если не подключается

- `Permission denied`: проверьте SSH-вход по ключу тем же пользователем, под
  которым запущен Obsidian; загрузите ключ в ssh-agent.
- `Host key verification failed`: подключитесь к серверу из терминала, проверьте
  его отпечаток и исправьте known_hosts при подтверждённой смене ключа.
- `hermes: not found`: задайте абсолютный путь к Hermes на сервере.
- Ошибка `cd` / рабочей папки: укажите существующий абсолютный серверный путь.
- Ошибка профиля: используйте `["acp"]` либо имя своего существующего профиля.
- Ошибка модели: очистите поле модели, чтобы использовать конфигурацию Hermes.
- Таймаут initialize: проверьте команду ACP и её зависимости на сервере.
  Обычный `hermes` с интерактивным интерфейсом вместо `hermes acp` не подходит.

Исходники Hermes, по которым проверена совместимость протокола:
- https://github.com/NousResearch/hermes-agent/blob/main/acp_adapter/entry.py
- https://github.com/NousResearch/hermes-agent/blob/main/acp_adapter/server.py

Лицензия MIT исходного проекта сохранена в `LICENSE`.

## Изменения 1.1.1: история

- Последовательная запись истории: параллельные сохранения не затирают новые сообщения старыми.
- `chats.json.bak` хранит предыдущую успешную версию. При повреждении основной истории используется копия.
- Если оба файла повреждены, запись блокируется с уведомлением; они не заменяются пустой историей.
- Ответ сохраняется по ходу генерации примерно каждые 2 секунды и при остановке/ошибке.
  При аварийном завершении последние 2 секунды могут не сохраниться.
- Новая ACP-сессия получает последние 80000 символов переписки текущего холста.
  Явный сброс контекста отмечает границу: более ранние сообщения остаются для просмотра, но не отправляются агенту.
- Текст, введённый во время ответа, остаётся в поле: прежняя имитация отправки указаний теряла такие сообщения.

При обновлении заменяйте `main.js`, `manifest.json`, `styles.css` с выключенным плагином.
Не удаляйте `data.json`, `chats.json`, `chats.json.bak` и файлы `.corrupt-*`.
Уже утраченные сообщения без копии восстановить невозможно.

## Как задать модель

В Obsidian: настройки плагина → «Модель Hermes» → ID модели → «Применить и проверить».
Либо в чате `/model ID_МОДЕЛИ`. Список `/model` берётся из ответа Hermes.
Пустое поле использует модель, настроенную в Hermes; локально скачивать API-модель не нужно.
Успешная проверка ACP не проверяет ключ LLM реальным запросом. Ошибка HTTP 401 требует
отдельной проверки выбранного провайдера, адреса и ключа в Hermes.

Интеграция DepSearch в эту версию не добавлена.

## Изменения 1.1.2: привязка холста

История, активная задача и ACP-сессия привязаны к полному пути `.canvas`. При
переименовании или перемещении файла внутри Obsidian ключ теперь автоматически
переносится на новый путь. Одинаковые названия холстов в разных папках не
пересекаются. Если файл переименовать вне Obsidian, пока приложение закрыто,
автоматически определить соответствие старого и нового пути невозможно.

## Изменения 1.1.3: глубокое расследование

В этой версии появился исследовательский план, развитие зацепок, прямые URL и
независимая проверка ключевых утверждений. Также добавлена защита от повторения
без изменения одинакового упавшего вызова. Числовая квота и жёсткое правило для
`hermes_tools.web_search` из первоначального варианта заменены в 1.1.4 на
адаптивный поиск до насыщения и проверку реально доступных инструментов.

В списке шагов теперь показывается краткий результат либо ошибка инструмента.
После третьего одинакового шага интерфейс выводит предупреждение о цикле. Сам
плагин не может принудительно остановить отдельный внутренний вызов Hermes, но
правила в запросе должны предотвращать наблюдавшийся цикл.

## Изменения 1.1.4: активный поиск до насыщения

Фиксированная квота из шести запросов удалена. Формулировки «глубокое
расследование» и похожие, а также команда `/deep`, включают режим активного
поиска: Hermes развивает каждую полезную зацепку в отдельную ветку и продолжает,
пока содержательно новые запросы перестают давать новые сущности, связи,
подтверждения или противоречия. В панели появилась кнопка «Глубокий поиск».

Жёсткого запрета на `from hermes_tools import web_search` больше нет. Такой
импорт разрешён, если он действительно работает в конкретном окружении Hermes;
после ошибки агент должен сменить способ вызова на доступный ACP-инструмент,
`web_extract`, браузер, `curl` или другую рабочую альтернативу, а не повторять
тот же упавший вызов.

## Изменения 1.1.5: переключатель Deep и только Hermes

В заголовке панели появился сохраняемый переключатель **DEEP**. В 1.1.6 его
состояние стало отдельным для каждого чата/холста. Команда `/deep` по-прежнему
разово включает тот же режим.

В Deep-режиме агент обязан использовать поиск только для обнаружения страниц,
открывать существенные источники и переходить на Playwright/`browser_exec`, если
страница динамическая, требует JavaScript, переходов, раскрытия элементов или
пагинации. Сниппет поисковика больше не считается проверенным источником.

Direct HTTP API, его пресеты, ключи и выбор движка удалены. Плагин работает
только через Hermes ACP: локально, по SSH или через собственную ACP stdio-команду.
При обновлении старые Direct API-поля автоматически удаляются из настроек.

## Изменения 1.1.6: интерфейс чатов, источники и размеры карточек

- **DEEP** хранится отдельно для каждого холста и переносится вместе с ним при
  переименовании. Переключение одного чата не влияет на остальные.
- Кнопка `+` создания холста перенесена в начало списка вкладок.
- Высота DEEP, селектора модели и квадратных кнопок заголовка унифицирована.
- Длинные названия связанных веток остаются внутри ответа и сокращаются
  многоточием; полное название видно во всплывающей подсказке и используется при
  нажатии.
- Под каждым ответом с URL отображается изначально свёрнутый список
  **«Источники»**. Ссылки извлекаются из текста и отдельного массива `sources`,
  который теперь запрашивается у Hermes.
- Расчёт высоты Canvas-карточек сделан компактнее. Создание, обновление и ручное
  выравнивание пересчитывают размер по актуальному тексту без прежнего большого
  запаса пустого пространства.

## Изменения 1.1.7: исправление высоты текстовых и фотокарточек

Оценка переноса обычного текста снова получила безопасный запас по ширине
символов и высоте строки, поэтому содержимое не должно превращаться во внутренне
прокручиваемую карточку. Обычные Markdown-ссылки на `.jpg`/`.png` без
восклицательного знака считаются ссылками, а не встроенными изображениями.

## Изменения 1.1.8: фиксированный запас фотокарточек

Для текстовой карточки со ссылками на изображения убирается один фиксированный
лишний запас высоты независимо от того, содержит она одну, две или больше
фотоссылок. Высота каждой строки ссылки при этом учитывается как обычно.
Расчёт обычных текстовых карточек не изменён.

## Изменения 1.1.9: восстановление после отмены и порядок чатов

После нажатия Stop чат остаётся занятым до фактического завершения отмены, поэтому
следующий запрос не попадает вслед за ещё работающим prompt. Отменённая ACP-сессия
удаляется и для следующего сообщения создаётся новая. Ответ `Internal error`,
полученный вследствие отмены, не показывается пользователю. Если Hermes не
завершил отмену за 1,5 секунды, плагин перезапускает только ACP-процесс; Obsidian
перезапускать не требуется.

Вкладки холстов после кнопки `+` сортируются по последней активности сообщений:
чат с самым новым сообщением находится слева, более старые уходят вправо.
Время активности сохраняется и переносится при переименовании холста.

## Изменения 1.2.0: редактирование сообщений и ветки

У каждого сохранённого пользовательского сообщения появилась кнопка
редактирования. После сохранения исправленного текста текущая переписка
обрезается в этой точке, ACP-сессия холста создаётся заново, а исправленный
запрос отправляется как начало новой ветки. Предыдущий вариант и его ответы не
удаляются: между вариантами можно переключаться стрелками под сообщением.

Для новых запросов сохраняется сжатый снимок Canvas перед отправкой. При
редактировании сообщения и переключении ветки плагин восстанавливает
соответствующее состояние карточек и связей. У сообщений, созданных до установки
1.2.0, такого снимка ещё нет, поэтому их текст и ответы разветвляются, но старые
изменения Canvas автоматически откатить невозможно.

Пока Hermes выполняет запрос, поле ввода остаётся доступным. Отправленное в это
время обычное сообщение помечается как следующее и автоматически передаётся
новым `session/prompt` после завершения текущего turn в той же ACP-сессии. Если
добавлено несколько follow-up сообщений, плагин объединяет их в один следующий
turn, сохраняя каждое отдельным сообщением в истории. Параллельные prompt к одной
сессии не запускаются.

Ложное предупреждение о трёх повторениях одного инструмента удалено: Hermes
может штатно присылать одинаковые названия нескольких вызовов. Неполезная строка
`[object Object]` для структурированных результатов инструментов также скрыта.

## Изменения 1.2.1: Deep без уведомлений и точный порядок чатов

Переключатель Deep больше не показывает всплывающие уведомления при включении и
выключении. Поясняющая строка про отдельный Deep-режим удалена из настроек.

Открытие холста и переключение ветки больше не меняют позицию вкладки. Список
обновляется только при фактическом добавлении пользовательского сообщения,
follow-up либо ответа Hermes. Старые метки, записанные простым открытием чатов,
сбрасываются при переходе на новую схему активности.

## Изменения 1.3.0: прокси в промпте и автоапрув по умолчанию

Вернулась маршрутизация через прокси, вырезанная при переходе на внешний ACP.
В локальном режиме появилось поле **«SOCKS5-прокси»**; заданный адрес попадает в
промпт Hermes отдельным блоком с примерами для `curl`, `requests` и `ALL_PROXY`,
а также с требованием ходить на 127.0.0.1 напрямую. Общая фраза про прокси в
базовом контракте осталась и работает, когда поле пустое. Подробности — в разделе
«Прокси для локального ACP».

Переключатель **«Автоматически разрешать инструменты»** включён по умолчанию.
Прежнее поведение (диалог подтверждения на каждый инструмент) возвращается
выключением тумблера.
