# VibeOSINT

Плагин Obsidian для OSINT-расследований на Canvas. Вы задаёте цель, агент
[Hermes](https://hermes-agent.nousresearch.com) её отрабатывает, находки ложатся
на холст деревом связанных карточек.

Hermes подключается по протоколу ACP: локально, на сервере через SSH или своей
командой. Десктоп-только, сборка не нужна.

## Установка

1. Скопируйте `main.js`, `manifest.json`, `styles.css` в
   `<ваш vault>/.obsidian/plugins/vibeosint/`.
2. Перезапустите Obsidian, включите плагин в **Settings → Community plugins**.
3. Откройте настройки плагина и настройте подключение.

При обновлении сначала выключите плагин, замените эти три файла и не трогайте
`data.json`, `chats.json`, `chats.json.bak`, `.corrupt-*` — там настройки и история.

## Подключение

Выберите транспорт и нажмите **«Применить и проверить»**. Кнопка проверяет
`initialize` и `session/new`; запрос к модели при этом не отправляется.
Поля сохраняются сразу, но активное подключение подхватит их только после этой
кнопки или перезапуска плагина. Активные запросы кнопка не прерывает —
сначала дождитесь или остановите их.

### Локальный Hermes · stdio

Hermes установлен на этой же машине. Команду оставьте пустой — плагин найдёт
`hermes` сам, — либо укажите полный путь. Аргументы `["acp"]`. Пустая рабочая
папка = папка vault.

Windows: указывайте `hermes.exe`. Если есть только Python-окружение — путь к
`python.exe` и аргументы `["-m", "acp_adapter.entry"]`. Файлы `.cmd` / `.bat`
запустить нельзя.

### Внешний Hermes · SSH

Hermes стоит и настроен **на сервере** (модель, ключи, инструменты). На машине с
Obsidian нужен только OpenSSH. Плагин запускает `hermes acp` на сервере и общается
с ним по stdio через SSH — открывать порты и поднимать HTTP/WS-мост не нужно.

Сначала убедитесь, что обычный `ssh user@server` работает: вход по ключу или через
ssh-agent, отпечаток сервера подтверждён. Пароль плагин спросить не может —
SSH запускается с `BatchMode=yes` без PTY, зашифрованный ключ добавьте в ssh-agent
заранее. `~/.ssh/config` (Host, ProxyJump, IdentityFile) учитывается, можно указать
алиас вместо `user@server`.

Путь к Hermes на сервере: `command -v hermes`.

| Поле | Значение |
| --- | --- |
| SSH-хост | `user@server` или алиас из `~/.ssh/config` |
| SSH-порт | пусто = из config или 22 |
| SSH-ключ | пусто = config / ssh-agent, либо `~/.ssh/id_ed25519` |
| Программа SSH | `ssh` или полный путь |
| Команда ACP | абсолютный путь с сервера, напр. `/home/user/.local/bin/hermes` |
| Аргументы ACP | `["acp"]`, либо `["-p","профиль","acp"]` для своего профиля |
| Рабочая папка | существующий абсолютный путь **на сервере**, напр. `/home/user` |
| Переменные окружения | обычно `{}` |

### Своя команда · stdio

Любая обёртка или другой ACP-агент. Команда — путь к исполняемому файлу без
аргументов и кавычек (запускается без shell), аргументы — JSON-массив строк.
В stdout — JSON-RPC ACP построчно, диагностика в stderr. `http://` и `ws://` здесь
не работают. Рабочая папка передаётся агенту как `session/new.cwd`, сама обёртка
стартует в папке vault.

## Как это работает

Canvas остаётся в Obsidian. Плагин отправляет агенту текстовый контекст текущего
холста и ваш запрос, получает потоковый ответ и применяет присланные JSON-блоки
локально. Копировать vault на сервер не нужно; доступа к вашим файлам и терминалу
у удалённого Hermes нет — его инструменты работают на сервере в своей рабочей папке.

На каждый холст — отдельная ACP-сессия. При обрыве создаётся новая и получает
последние 80 000 символов переписки этого холста (без повторной отправки старых
JSON-действий). Состояние инструментов при этом не восстанавливается, история
плагина живёт в `chats.json`.

## Модель

Настройки → **«Модель Hermes»** → ID → «Применить и проверить». Или в чате
`/model ID`; `/model` без аргумента показывает список, который вернул Hermes.
Пустое поле = модель из конфигурации Hermes. Смена через `/model` применяется к
текущему холсту и новым сессиям, уже открытые чужие сессии сохраняют свою модель.

Проверка подключения не проверяет ключ провайдера. Если получаете HTTP 401 —
разбирайтесь с провайдером, адресом и ключом в самом Hermes.

## Прокси

Поле **«SOCKS5-прокси»** доступно в локальном режиме. Адрес передаётся Hermes в
промпте вместе с инструкцией повторять через прокси запросы, упавшие с 403,
RegionError, Connection Reset или блокировкой Cloudflare. Пустое поле — прокси не
упоминается вообще.

Формат: `socks5h://127.0.0.1:2080`, `http://proxy:8080` или просто `127.0.0.1:2080`
(подставится `socks5h`). Схема `socks5h` резольвит DNS на стороне прокси и не даёт
утечки DNS. Поддерживаются `socks5h`, `socks5`, `socks4`, `http`, `https`.

Для SSH поля нет: удалённый Hermes ходит в сеть с сервера, и `127.0.0.1:2080` там
не существует. Задавайте прокси в конфигурации Hermes на сервере или через
«Переменные окружения»: `{"ALL_PROXY":"socks5h://127.0.0.1:2080"}`.

## Разрешения и секреты

Тумблер **«Автоматически разрешать инструменты»** включён по умолчанию: запросы
разрешений от Hermes подтверждаются без диалога. Выключите его, чтобы
подтверждать каждое действие вручную. Плагин не навязывает Hermes YOLO-режим и не
отключает проверки его конфигурации.

По SSH передаются только переменные из поля «Переменные окружения» — локальные
ключи и прокси на сервер не копируются. Этот JSON лежит в `data.json` открытым
текстом, так что секреты лучше держать в конфигурации Hermes. Приватный SSH-ключ
остаётся локальным, в настройках хранится только путь к нему.

## Если не подключается

| Ошибка | Что делать |
| --- | --- |
| `Permission denied` | проверьте вход по ключу тем же пользователем, под которым запущен Obsidian; загрузите ключ в ssh-agent |
| `Host key verification failed` | подключитесь из терминала, сверьте отпечаток, поправьте known_hosts |
| `hermes: not found` | укажите абсолютный путь к Hermes на сервере |
| ошибка `cd` | рабочая папка должна существовать и быть абсолютной |
| ошибка модели | очистите поле модели |
| таймаут `initialize` | проверьте команду и её зависимости; интерактивный `hermes` вместо `hermes acp` не подойдёт |

## История версий

- **1.3.0** — прокси вернулся: поле «SOCKS5-прокси» в локальном режиме, адрес идёт
  в промпт отдельным блоком с примерами для `curl`, `requests`, `ALL_PROXY`.
  Автоапрув инструментов включён по умолчанию.
- **1.2.1** — Deep без всплывающих уведомлений; вкладки переупорядочиваются только
  при реальных сообщениях, а не при открытии холста.
- **1.2.0** — редактирование сообщений с ветками и откатом Canvas по снимкам;
  follow-up во время генерации склеиваются в следующий turn.
- **1.1.9** — корректная отмена: чат занят до фактического завершения Stop, сессия
  пересоздаётся, зависшая отмена перезапускает только ACP-процесс. Вкладки
  сортируются по последней активности.
- **1.1.6–1.1.8** — свёрнутый блок «Источники» под ответами, DEEP отдельно для
  каждого холста, компактный и более точный расчёт высоты карточек.
- **1.1.5** — тумблер **DEEP** в шапке. Direct HTTP API, его пресеты и ключи
  удалены: только Hermes ACP. Старые поля вычищаются из настроек автоматически.
- **1.1.3–1.1.4** — исследовательский план, развитие зацепок, проверка ключевых
  фактов по двум источникам, поиск до насыщения вместо фиксированной квоты,
  защита от повторения упавшего вызова.
- **1.1.2** — история и сессия привязаны к пути `.canvas` и переезжают при
  переименовании внутри Obsidian.
- **1.1.1** — надёжная история: последовательная запись, `chats.json.bak`,
  автосохранение по ходу генерации, отказ вместо затирания при повреждении.
